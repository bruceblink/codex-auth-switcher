# Codex Auth Switcher 用户指南

本指南适用于 Rust + GPUI Kit 桌面程序。运行程序不需要 Python、Rust 或 Ramag。

## 安装

- Windows：运行 `Codex-Auth-Switcher-<version>-windows-x64-setup.exe`，按向导安装到当前用户目录。安装完成后从开始菜单启动。
- Debian/Ubuntu：使用系统包管理器安装 `Codex-Auth-Switcher-<version>-linux-amd64.deb`，再从应用菜单启动。
- 其他 Linux x64：为 `Codex-Auth-Switcher-<version>-linux-x86_64.AppImage` 添加执行权限后运行。
- macOS：按处理器下载 `-macos-arm64.dmg` 或 `-macos-x86_64.dmg`。挂载后把应用拖入 Applications，再从该目录启动。

下载后请用同一版本的 `SHA256SUMS.txt` 检查文件。当前安装包没有 Windows 证书签名或 macOS 公证。若系统阻止运行，请核对来源与校验值，不要关闭系统安全保护。历史版本 `v0.3.0` 是原始可执行文件，不包含安装向导。

## 开始使用

1. 启动已安装的 Codex Auth Switcher。Windows Release 使用图形子系统，不会额外打开终端窗口。
2. 检查“配置目录”。默认值来自 `CODEX_HOME` 或 `%USERPROFILE%\.codex`。
3. 首次使用时点击“创建默认配置”；已有配置时点击“初始化模式”或“补齐模式”。工具读取当前 `config.toml`、`auth.json` 和可识别的备份文件。
4. 检查“当前实际模式”。它显示磁盘上的认证模式。“模式存档”列出已保存的订阅和 API key 参数，不代表当前选择的目标已生效。
5. 选择目标模式。需要时编辑 provider、Base URL 或 API key。输入框留空时，工具使用目标模式已保存的认证。
6. 点击“预览变更”，进入“确认切换”页。检查目标模式、配置目录和变更字段。预览不显示认证正文，也不会写入配置。
7. 需要调整时点击“返回修改”；点击“取消预览”可撤销本次确认。两种操作都会保留输入。
8. 关闭 Codex，再在确认页点击“应用切换”。成功后程序返回配置页，并提示重启。重新启动 Codex 后，请新建会话。

Windows 用户可以点击底部的“重启 Codex”，确认后重新打开已安装的 Codex 桌面应用。工具只发送正常关闭请求，不强制结束进程；如果应用未退出或启动失败，会提示手动重启。请先保存工作；重启会中断正在生成的回复。有尚未应用的变更预览、未保存的 API key 或模型目录时，重启按钮不可用。使用自定义配置目录时，请确认 Codex 也使用同一目录。Linux 和 macOS 当前需要手动重启。

配置页底部显示“预览变更”和“重启 Codex”；确认页底部显示“返回修改”“取消预览”和“应用切换”。长内容可以垂直滚动，底部操作保持可见。目标与当前配置一致时，“应用切换”不可用。

如果手动编辑了配置目录，请先点击“刷新状态”，让界面读取新目录后再预览切换。若上次切换留下未完成的恢复记录，请先点击“补齐模式”。

首次使用时，工具只创建缺失的 `config.toml`，使用 Codex 内置 `openai` provider 和官方默认模型。文件认证使用 `cli_auth_credentials_store = "file"`。工具不会创建占位的 `auth.json`：订阅用户先在 Codex 中完成登录；API key 用户可在输入框输入密钥，预览后应用。使用第三方 API 地址时，还需填写自定义 provider ID。

工具只在初始化、导入或用户确认“应用切换”时写入配置。文件操作在后台运行。工具不请求远程 API，因此“已就绪”不代表 key 有效、订阅未过期或服务可用。

## 导入模式来源

在目标模式区域，使用配置按钮导入 TOML，使用认证按钮导入认证 JSON。导入只更新加密模式存档，不会立即切换当前认证。

切换时，工具会把当前模式参数和认证保存到加密模式存档。若配置发生变化，工具会创建 `config.toml.bak-*`，其中只包含当前模式参数和选中的 provider，不包含共享设置或凭据。活动 `config.toml` 中的 MCP、项目、插件和 shell 环境设置会继续保留。显式导入的配置与认证会保留在目标模式中。即使目标模式当前正在使用，切换到另一模式再切回时仍会应用导入的数据。导入不会立即切换当前认证。

API key 输入框会遮盖输入内容，并显示首尾提示。程序只使用输入框里的密钥或已保存认证，不读取 `AUTOCODE_API_KEY` 或 provider `env_key` 指向的环境变量。输入框密钥成功应用后，程序会将它写入 Windows 当前用户的持久环境变量 `AUTOCODE_API_KEY`。切换失败时不会写入。预览会显示认证来源，但不会显示密钥。应用切换后，输入框会清空。

## 管理 Codex 模型选项

1. 在 `config.toml` 中设置 `model_catalog_json`，指向要由 Codex 使用的本地模型目录。相对路径以 `config.toml` 所在目录为基准。未设置时，工具不会编辑 `models_cache.json` 缓存。Codex 的配置文件或启动参数可能覆盖主配置。
2. 点击顶部的“模型目录”按钮。若 `config.toml` 已设置 `model_catalog_json`，点击“读取已配置目录”；也可以点击“选择 JSON 文件”并选择已有模型目录文件。
3. 选择模型，编辑模型 ID、显示名称、可见性、优先级、默认推理级别和支持的推理级别。
4. 点击“复制模型”可新增条目。新条目会复制所选模型的其他能力参数；修改模型 ID 后，请确认这些能力参数与新模型相符。
5. 点击“保存”。工具会先在目录文件旁创建备份，再原子写入文件。

文件选择器会先验证 JSON。选择成功后，工具会显示文件路径和模型列表，并更新当前模式的目录设置；另一模式的设置不变。请重启 Codex 让目录设置生效。取消选择或验证失败时，工具不会替换当前模型列表。若 `config.toml` 不存在，请先初始化配置。存在未保存的模型改动时，请先保存或放弃，再选择文件。

模型目录页显示当前实际模式和配置目录。保存后保留当前选中的模型；“放弃”恢复到上次读取或保存的内容。未保存改动会阻止应用模式切换和更换配置目录。

工具会保留模型文件中未提供编辑控件的字段。若 Codex 或其他程序在读取后改动该文件，保存会停止；重新读取后再编辑。保存后重启 Codex，让模型选择菜单重新读取模型目录。

模式快照也会保留 Codex 的模型详细度、自动压缩设置、模型指令文件、审查模型以及 ChatGPT/OSS provider 字段。旧模式存档没有这些字段时，切换会沿用活动配置中的值；导入的新配置提供字段后，预览会列出并应用对应变化。

## 本地数据和备份

第二版将模式存档保存在 `%USERPROFILE%\.codex\auth-switcher-v2`，或对应 `CODEX_HOME` 下的 `auth-switcher-v2` 目录。`modes.enc` 和 `pending.enc` 使用 AES-256-GCM；`vault.key` 与密文分开保存。Windows 目录 ACL 仅允许当前用户和 SYSTEM 访问。

此加密只保护工具自己的模式存档。复制 `vault.key` 和密文后可以解密存档，所以请按敏感数据管理备份。Codex 使用的 `auth.json` 仍保持 Codex 格式。工具不会修改 `autocode.config.toml`，也不会改变 MCP、项目或插件设置。

第一版 DPAPI 存档不会由当前版本读取或覆盖。若检测到旧版未完成的 `pending.dpapi` 写入，先保留当前 Codex 文件。需要恢复时，从 Git 历史提交 `d2bb002` 取回对应历史版本，在原 Windows 用户账户下恢复该记录。不要用当前程序尝试读取旧存档，也不要删除旧存档。

## 卸载

Windows 使用系统“已安装的应用”中的卸载入口；Debian/Ubuntu 使用包管理器移除；macOS 删除 Applications 中的应用；AppImage 删除下载文件即可。

卸载不删除 Codex 配置目录、`auth.json`、加密模式存档或模型文件。安装程序不添加后台服务或开机启动项。
