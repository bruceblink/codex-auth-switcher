# Rust + egui 第二版开发计划

更新日期：2026-10-31。

## 1. 目标与当前基线

项目维护一个 Rust 图形界面版本。桌面层使用 egui/eframe 0.37.0 和 Wgpu，业务核心由独立的 `switcher-core` crate 提供。Windows x64 是当前原生验收目标；CI 同时为 Windows、Linux 和 macOS runner 生成对应架构的 Release 可执行文件。

当前基线已经覆盖模式存档、配置预览、认证切换、失败恢复、模型目录编辑和 Windows 原生窗口验收。CLI、Python 第一版、GPUI 运行依赖及其专用入口已从当前 workspace 移除；相关记录保留在历史文档中。

## 3. 当前实现范围

### 3.1 模式与认证

- 订阅和 API 模式分别保存 provider、模型、推理参数和认证。
- 导入 TOML 或 JSON 只更新加密模式存档，不直接替换活动文件。
- 应用前生成受控预览，并在应用时重新检查 `config.toml`、`auth.json` 和模式存档是否变化。
- 配置备份只包含模式参数和选中的 provider；MCP、项目、插件、代理、shell 环境和其他共享设置保留在活动配置中。
- API key 只来自输入框或已保存认证。输入框使用密码遮罩，应用成功或失败后清空。
- 默认 API 地址由 `switcher-core::config::DEFAULT_API_BASE_URL` 统一提供，界面和初始化逻辑共用同一值。

### 3.2 桌面交互

- 文件和加密操作运行在工作线程，界面保持响应。
- 修改配置目录后清除旧状态，必须刷新后才能预览；有未保存模型目录改动时锁定目录编辑。
- 检测到 `pending.enc` 时显示恢复提示，并要求先执行“补齐模式”。
- 预览无配置或认证变化时显示明确提示；预览和应用按钮根据当前状态启用或禁用。
- 模式卡片显示当前状态、provider、模型、推理级别、配置来源和认证来源。

### 3.3 模型目录

- 可编辑模型 ID、显示名称、可见性、优先级、默认推理级别和支持的推理级别。
- 复制模型时保留未编辑的能力字段；保存前校验数量、格式、重复 ID 和推理级别关系。
- 保存前检测外部修改，创建不覆盖的 `models-codex.json.bak-*` 备份，并保留未知顶层字段。

## 4. 接受条件与验证证据

### 4.1 功能接受条件

- 订阅/API 模式可以分别初始化、预览、应用和回切。
- 缺少匹配认证、无效 URL、无效模型目录和外部文件变化会停止操作，并保留原文件。
- 写入中断后可以通过加密恢复记录恢复配置、认证和模式存档。
- API key 不出现在预览、错误文字、日志、明文备份或测试输出中。
- 模型目录保存不会覆盖并发修改，也不会丢失未编辑字段。

### 4.2 自动验证

当前 workspace 的测试覆盖核心存储和 egui 按钮流程，包括初始化、TOML/JSON 导入、预览、模式往返、文件选择器取消、刷新、模型目录复制和备份。标准检查命令为：

```powershell
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --locked
.\scripts\package-windows.ps1
.\scripts\test-v2-native-ui.ps1
```

Linux/macOS 打包命令为 `./scripts/package-unix.sh`。CI 产物包含版本化可执行文件、带用户指南的 `tar.gz` 归档和对应 SHA-256 文件；Windows 产物还包含便携 ZIP。

### 4.3 Windows 原生验收

原生脚本使用隔离临时目录和合成认证数据，验证：

1. Release 可执行文件使用 Windows GUI 子系统。
2. 初始化、目标模式选择、预览、API 应用和订阅回切完成。
3. MCP、项目和其他共享设置保持不变。
4. 模型目录可以读取、复制、编辑、保存并创建备份。
5. 原生文件选择器和真实窗口中的控件可见、可访问、可操作。

视觉验收使用真实窗口截图；可访问性树和控件自动化结果不能替代视觉检查。当前已在 100% 显示缩放下验证 Wgpu 窗口和模型目录编辑器；Headless 截图不用于判断中文字体和最终字形。

## 5. 下一阶段计划

### P1 发布质量维护

- 每次发布运行格式检查、Clippy、workspace 测试，生成 Windows、Linux 和 macOS Release 构件，并在 Windows 上运行便携包和原生验收。
- 本地和 CI 使用 Rust stable 工具链，当前验证版本为 1.99.1；格式检查、Clippy 和 workspace 测试使用同一稳定版本。
- 记录 Windows 原生窗口截图、版本号、构建产物和隔离目录检查结果。
- 保持 `main` 分支只包含已验证的提交，发布包不依赖 Python、Rust 或包管理器环境。

退出标准：检查命令和三平台构建全部通过，Windows 便携包可在干净环境启动，原生验收目录中没有真实凭据。

### P2 Codex 配置兼容性维护

- 关注 Codex `config.toml` 的模式字段、provider 能力字段和认证 JSON 结构变化。
- 当前已纳入模型详细度、自动压缩范围与阈值、模型指令文件、审查模型、ChatGPT 地址和 OSS provider 字段；这些字段会进入模式快照和预览。
- 新字段在旧加密模式存档中缺失时沿用活动配置，避免升级工具后切换一次就清空旧配置；目标快照提供字段时才应用新值。
- 为新增模式字段补充保留式编辑、预览和回滚测试。
- 继续保留未知模型目录字段，并在格式变化时先拒绝保存再提示重新读取。

退出标准：新增字段有明确保留或拒绝策略，旧数据不会被静默覆盖，错误文字不泄露输入内容。

### P3 原生体验扩展

- 当前迭代：固定底部的预览、应用和操作结果区域；模式卡片默认显示常用字段，其他参数和来源可展开查看；长预览在列内换行，状态文字使用中文。
- 接受条件：默认 920 × 640 和最小 720 × 560 窗口中，生成长预览后仍能直接看到并操作底部按钮；滚动内容不覆盖操作区；模式往返与模型目录功能保持正常。
- 验证命令：格式检查、严格 Clippy、workspace 测试、Windows Release 打包和隔离原生 UI 验收；100% 缩放下通过 Computer Use 检查真实窗口。
- 回滚范围：本轮只调整桌面布局、显示文字和对应测试。模式存档格式、活动配置写入和认证处理不变；撤回本轮提交即可恢复旧布局。
- 2026-10-31 本机证据：Rust stable 1.99.1 的 Release 窗口在默认和缩小尺寸下保持底部操作区可见；Computer Use 在隔离配置目录生成长预览并应用 API 模式。24 项核心测试与 7 项桌面测试通过，新增测试覆盖 920 × 640、720 × 560、预览滚动和无变化时禁用应用。
- 在 Windows 100% 验收稳定后，评估 150% 和 200% DPI 下的布局、滚动、输入法和文件选择器行为。
- 补充键盘焦点、Tab 顺序、长路径、窗口缩放和高对比度主题检查。
- 需要真实环境或人工视觉判断的项目单独记录证据，不用 Headless 结果替代。

退出标准：每个新增显示缩放或可访问性场景都有可复现步骤和截图证据。

## 6. 明确不在当前计划内

- 远程 API 请求、认证有效性或订阅状态验证。
- 系统钥匙串、跨账户迁移、无人值守登录和旧 DPAPI 存档迁移。
- `autocode.config.toml`、MCP、项目、插件和共享代理设置的管理。
- 在当前 workspace 中并行维护第二套 GUI 框架实现。

## 7. 数据边界与回滚

测试只使用仓库构建目录或系统临时目录中的合成数据，不读取真实 Codex 认证。当前程序不删除或覆盖第一版 DPAPI 存档；检测到旧版 `pending.dpapi` 时停止并提示使用历史版本恢复。

模式存档位于 `CODEX_HOME/auth-switcher-v2`，`modes.enc` 和 `pending.enc` 使用 AES-256-GCM，`vault.key` 与密文分开保存。Windows 状态目录仅允许当前用户和 SYSTEM 访问。回滚依赖加密恢复记录和应用前的文件快照；发现外部修改时停止覆盖并保留恢复记录。

egui 是当前唯一维护的桌面实现。若未来更换框架，应作为单独迁移项目处理，不在当前 workspace 中并行保留第二套实现。
