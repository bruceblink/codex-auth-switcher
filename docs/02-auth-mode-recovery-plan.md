# 认证模式恢复计划

## 范围与依据

当前 API 模式使用 `OpenAI` provider 和 `auth.json` 中的 API key。切换前的订阅配置使用 `openai` provider，订阅认证仍保存在已有 `auth.json.bak` 中。两种模式还使用不同的模型、推理级别和上下文参数。原来的单字段切换不能恢复认证。

1. 使用 TOML 解析器保留式编辑配置，按模式保存模型参数和活动 provider 定义。
2. 从当前文件和匹配模式的已有备份导入初始状态。只导入模式相关字段，不整份覆盖旧配置。
3. 在 Windows 上使用数据保护 API（Data Protection API / DPAPI）保存认证状态。认证状态不进入项目、日志或明文备份。
4. 切换时保存离开模式的最新状态，恢复目标模式的配置和认证；失败时恢复切换前状态。
5. 修正 GUI、CLI、说明文档，并添加隔离目录回归测试。

## 接受条件

- `openai` 与 `OpenAI` 大小写保持原样。现有 API provider 的 `/v1`、`requires_openai_auth` 和其他能力字段不被默认值覆盖。
- 两种模式分别恢复模型、推理级别、上下文参数和认证。缺少目标认证时停止切换，并给出操作提示。
- 保留当前 MCP、项目、插件、代理和其他共享设置，不恢复旧备份中的无关字段或凭据。
- 配置在写入前解析校验；备份不覆盖、不含明文凭据。认证状态通过 DPAPI 加密，不创建 `auth.json` 明文备份。
- 保存前检测外部修改；写入失败时恢复活动配置和认证。重复切换不生成无效配置。
- 验收使用隔离目录。真实 `.codex` 只初始化模式状态，不切换当前正在使用的 API 模式。

## 验证

```powershell
py -3 -m unittest discover -s tests -v
py -3 -m compileall -q main.py src tests
py -3 main.py --target status
```

使用 Computer Use 在真实窗口中检查状态、切换结果、错误提示和布局。模型组合按本机模型目录核对；不把本地文件切换验收描述为远程认证成功。

## 回滚边界

代码改动限于本项目。模式状态保存在 Codex 用户目录的 `auth-switcher` 子目录。配置恢复只使用本次生成的无凭据备份；认证失败回滚使用内存中的原始数据，不创建明文认证备份。当前会话不执行真实模式切换。
