## 原生窗口

使用 Computer Use 操作真实 Tkinter 窗口，数据位于 `build/ui-acceptance`。所有认证数据均为虚构测试数据。

1. 初始化后，两种模式显示为已就绪。操作记录显示配置和认证的来源。
2. API → 订阅后，provider、模型、推理级别和认证类型均更新。
3. 订阅 → API 后，状态恢复为 API 参数。
4. 输入虚构 key 后，只显示首尾字符；应用后输入框清空。
5. 输入非法 URL 后，切换被拒绝，错误对话框可见，当前模式保持 API。
6. 当前默认窗口中，控件和文字无明显重叠。

Tkinter 的 UI Automation 树主要返回窗格，操作依赖坐标。没有验证读屏完整性、多显示器或多种 DPI。
