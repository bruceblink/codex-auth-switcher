# 第二版 GPUI Kit 开发计划

日期：2026-10-24。第一版基线：`d2bb002`。第二版按用户决定使用 Rust + gpui-kit。

## 范围与选择

以 `F:/project/ramag-platform` 已验证的 `gpui-kit 0.7.3` 启动、Root、输入和主题用法为参考，在本仓库实现独立应用。Ramag 保持原样；不复制数据库、消息、系统钥匙串、插件和平台存储依赖。只使用 Kit 的公开组件，不复制 Ramag 的产品代码或资源。

1. Rust 核心负责 TOML 保留式编辑、认证状态、初始化、预览、切换、外部修改检测和失败恢复。Python 第一版保留为迁移参考。
2. 新存档使用 AES-256-GCM，随机本地密钥与密文分开保存，移除 DPAPI 运行时依赖。密钥缺失或密文损坏时停止，不重建覆盖。
3. gpui-kit GUI 提供当前状态、两种模式、配置目录、输入参数、导入来源、变更预览、应用和错误提示。耗时文件操作在后台执行。
4. CLI 提供只读状态、初始化、预览、切换和隔离演示目录。API key 不作为命令行参数或日志输出。
5. 旧 DPAPI 存档不覆盖、不删除。新格式从当前配置和有效备份初始化；旧 pending.dpapi 未处理时停止。

## 接受条件

- API 与订阅分别恢复 provider、模型、推理参数和认证；共享配置保持当前值，不依赖或修改 autocode.config.toml。
- UI 输入优先于环境变量，空值保留目标模式。新界面显示输入 key 首尾，中间脱敏，应用后清空。
- 预览只返回受控字段，不显示令牌、API key 或共享配置正文。应用前重新检查文件与预览快照；变更时要求重新预览。
- 密钥创建不覆盖，使用用户文件权限；密文认证记录版本和用途。写入和恢复保留加密记录，进程中断后可恢复，外部修改时不覆盖。
- 密钥和真实认证不进入源码、测试、构建日志或 Git。正式验收只操作隔离数据。
- 默认使用独立可执行文件，不要求 Python 或 Ramag 运行。Windows 为原生验收平台，其他平台只按实际 CI 结果报告。
- Headless GPUI 测试实际调度初始化、导入、目录选择、刷新、模式选择、预览和应用按钮。文件选择器使用虚构来源，不启动系统对话框。

## 验证

```text
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace --locked
cargo build --release --locked
.\scripts\test-v2-headless.ps1
.\scripts\test-v2-native-ui.ps1
.\scripts\package-windows.ps1
```

测试覆盖第一版往返和故障场景，增加加密用途、缺失密钥、认证损坏、预览过期、资源上限和锁。保留第一版 Python 测试。Headless GPUI 测试验证实际按钮事件与业务状态变化。另用 Computer Use 验收真实 GPUI Kit 窗口，检查错误提示、中文输入、键盘焦点、密钥掩码、窗口缩放和不同 DPI；headless 结果不替代原生验收。远程认证和旧会话 provider 迁移不适用。

## 回滚边界

改动限于本仓库新增 Rust workspace、文档与 CI。真实 Codex 配置和第一版 DPAPI 数据不执行迁移或切换。新存档位于独立 `auth-switcher-v2` 子目录。第二版失败时继续使用第一版；不删除用户数据。验证通过后独立提交并推送。
