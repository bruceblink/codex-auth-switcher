## 本轮模型编辑打磨

- 范围：重新设计原生 UI 和完整操作流程。保留认证、备份、恢复和更新下载的现有实现。模型页增加直接打开 JSON、新增模型、搜索、参数编辑和单独关联操作；增加配置检查与保守清理。每个独立功能验证后单独提交、推送。本轮完成验证后发布 `v0.5.1`。
- 设计方式：图像生成工具当前不可用，使用现有 GPUI Kit 组件制作原生界面，以真实窗口迭代检查，不把图片当成可交互界面。
- 视觉规则：白色主工作区、浅灰导航栏、绿色主要按钮。常用操作用正文尺寸，说明用次级文字。正常窗口使用左侧导航，最小窗口使用顶部导航，操作栏固定在底部。
- 切换流程：先显示当前实际模式与配置目录，再选择目标模式、填写参数和导入资料。预览页明确显示目录、当前模式、目标模式和变更。应用后引导重启和新建会话，不自动重启用户的 Codex。
- 初始化条件：只有 `config.toml` 和 `auth.json` 都不存在时，提示初始化。只缺配置时提示补齐配置；只缺认证时提示登录、导入或输入密钥。已有文件不因缺少内部模式存档而提示初始化；预览时按需建立内部存档，不更改活动认证。
- 配置检查：检查 TOML 语法、部分常用字段类型和已核实的过时项。未知字段不删除，不将有限规则检查描述为完整 Codex 验证。清理前显示待删除项，用户确认后核对文件版本，创建只包含删除项的备份，再更新原文件。
- 模型流程：直接打开 JSON 只加载文件，不修改 Codex 配置。新增模型使用所选条目作能力模板，用户修改 ID 和参数后保存到打开的文件。保存前校验、检查外部改动并备份。将文件关联到当前模式是独立操作。
- 验收条件：未保存时不能换文件或关联；清空优先级或只输入负号时显示整数提示，禁止保存、换选模型和复制条目；输入保留，直到用户修正或放弃。合法字段编辑仍可跨模型保留。所有改动恢复到读取基线后清除未保存状态。搜索不产生文件改动。
- 验证命令：在同一 PowerShell 进程初始化仓库支持的 MSVC/CMake 环境，核对 `rustup run stable rustc -Vv`，运行 `cargo fmt --all -- --check`、`cargo check --workspace --all-targets --locked`、`cargo clippy --workspace --all-targets --locked -- -D warnings`、`cargo test --workspace --locked` 和 `cargo build --release --locked`。
- 界面验收：使用 Computer Use 和隔离配置，检查无效优先级提示、按钮状态、修正、放弃及合法草稿换选。检查正常窗口和最小窗口的滚动与固定操作栏。不得读取真实认证或重启当前 Codex。
- 回滚范围：只撤回本轮界面、模型文件编辑流程、相关测试和说明改动。代码回滚不会还原用户已保存的模型文件；文件恢复仍使用保存前备份。
- 收尾顺序：修复模型上限与副本元数据恢复，清除测试调试输出；运行 Rust 检查后构建真实窗口。验收四种配置/认证存在状态、独立 JSON 打开/搜索/新增/保存/关联、无效输入保护、配置检查/清理取消和外部改动保护，以及 1040 × 740 和 720 × 560 的布局。先提交完整交互改版，再独立提交配置规则和备份反馈改进。原生测试不读取真实认证、不应用合成 API key 到用户环境、不重启当前 Codex。

## 目标

维护一套 Rust + GPUI Kit 桌面程序，用于管理 Codex 的订阅与 API 模式。程序保留用户的共享配置，安全保存模式档案，并在写入失败或进程中断时恢复原状态。

当前工作区只维护 `switcher-core` 和 `switcher-desktop` 两个 Rust crate。GPUI Kit 是唯一桌面框架。产品不提供 Python 运行时或命令行界面。

## 架构与平台范围

- `switcher-core` 负责 TOML 与 JSON 校验、模式存档、预览、文件写入、文件锁、备份和恢复。独立的 `update` 模块负责 GitHub 版本检查、平台安装包选择、下载与校验，不接收认证或模式配置。
- `switcher-desktop` 使用 GPUI Kit 0.8.1 提供一个原生窗口。输入实体在界面状态更新时复用。文件、加密和进程操作在后台运行。渲染过程不执行文件访问，也不使用定时全量刷新。
- Rust 工具链使用 stable。`rust-toolchain.toml`、CI 和本地构建均使用 stable、Clippy 和 rustfmt。
- GitHub Actions 检查 Windows x64、Linux x64 和 macOS ARM64。打包脚本提供 Windows 安装向导、Linux `.deb`/`.AppImage` 和 macOS `.dmg`，发布流程生成统一 SHA-256 清单。Windows 已通过本机装卸测试，四个安装包也已通过对应平台 CI 的完整构建与检查。
- Windows 支持原生重启 Codex；Linux 和 macOS 需要用户手动重启。单实例锁按当前 OS 用户生效，不受 `CODEX_HOME` 影响。
- 程序不向 Codex 或 OpenAI 服务发送认证请求，不验证 API key 或订阅令牌。软件更新只访问本项目的 GitHub Release。程序不修改 `autocode.config.toml`，也不替换 Codex 的系统钥匙串认证。

## 当前功能

- 首次使用时创建缺失的 `config.toml`，使用 Codex 内置 `openai` provider 和官方 API 地址 `https://api.openai.com/v1`。工具不会创建占位 `auth.json`。
- 用户可以导入订阅和 API 模式配置与认证，预览变更，再应用模式切换。预览过期、输入无效、活动文件被外部修改或恢复尚未完成时，程序会停止写入。
- 模式切换保留 MCP、项目、插件、代理和其他共享设置。`auth.json` 保持 Codex 格式。模式档案存储在 `.codex/auth-switcher-v2/`。
- 模型目录页可以读取已配置的 JSON 文件，也可以选择现有文件并设置当前活动模式的 `model_catalog_json`。另一模式的路径保持不变。路径可为绝对路径或相对 `config.toml` 所在目录的路径。
- 模型编辑器支持修改 ID、显示名称、可见性、优先级、默认推理级别和支持的推理级别。保存前校验数据，并检测目录文件和配置路径是否已变化。
- Windows 重启操作需要用户确认。程序使用正常关闭请求，不强制结束 Codex 进程。

## 安全与恢复

- `modes.enc` 和 `pending.enc` 使用 AES-256-GCM。`vault.key` 与密文分开存放。Windows 状态目录只允许当前用户和 SYSTEM 访问。
- 配置更新前创建不覆盖的 `config.toml.bak-*`。该备份只包含当前模式参数和选中的 provider，不复制共享设置或凭据。模型目录保存会在 JSON 文件旁创建独立备份。
- 同步配置、认证和加密档案时先写入恢复记录。进程中断后，初始化流程按记录恢复。密钥缺失、密文损坏、外部修改或恢复冲突时，程序停止并保留数据。
- API key 只来自界面输入或已保存认证。只有成功应用后，程序才会写入 Windows 当前用户的 `AUTOCODE_API_KEY` 环境变量。界面不会显示完整密钥，预览和错误不显示密钥。
- 旧版 DPAPI 数据不由当前程序读取。若旧版存在未完成的 `pending.dpapi` 写入，应使用对应历史版本恢复。
- 自动化测试使用临时目录和合成认证。测试不得读取或修改真实 `.codex` 文件，也不得重启用户当前运行的 Codex。

CI 在三种目标平台运行格式检查、workspace check、Clippy 和测试。`Desktop Release` 在同一提交的质量检查通过后构建安装包，核对格式、架构、版本、包内文件和 SHA-256。Windows 工作流另外运行隔离目录下的原生 UI 自动化和受控安装、卸载测试。UI 验收记录必须区分 headless、Windows 真实窗口、Linux/macOS 真实窗口、发布构件和正式发布结果。

## 回滚

- 每项独立功能完成验证后单独提交。需要撤回功能时，撤回对应提交，不重置其他工作。
- GPUI Kit 迁移前的代码恢复点是 Git 提交 `05a317e`。恢复该版本时使用 Git 历史，不在当前 workspace 并行维护第二套 GUI。
- 回滚代码不会恢复用户数据。配置路径变更使用 `config.toml.bak-*`，模型文件保存使用 JSON 旁的备份。未完成的事务由 `pending.enc` 恢复；不要手动删除密钥、密文、恢复记录或 Codex 认证。
